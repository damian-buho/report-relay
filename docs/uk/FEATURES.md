# Можливості

## Можливості проєкту

### Повільний збирач ніколи не сповільнює браузер

- Точка приймання відповідає щойно звіт перевірено й поставлено в чергу, ніколи після експорту, тож зупинений збирач коштує звітів, а не завантажень сторінок.
- Черга експорту має обмежену місткість: коли вона заповнена, записи відкидаються й рахуються, а не черга зростає безмежно.
- Експорт повторює спроби з експоненційним відкатом і розкиданням у межах загального часу, тож мертвий збирач затримує зупинку на обмежену величину і ні на більше.
- Зупинка в порядку спрацьовування спорожнює чергу в межах налаштованого часу; `/healthz` і `/readyz` живуть на окремому адміністративному порту відкритої точки приймання.

### Вбудовується без змін у встановлення OpenTelemetry

- Налаштування насамперед через середовище під `REPORT_RELAY_*`, а експортер читає стандартні змінні `OTEL_EXPORTER_OTLP_*`, тож власний блок клієнта не потрібен.
- Сервіс звітує про себе тим самим каналом: отримані, прийняті та відкинуті звіти, кожен відкинутий із причиною, що його спричинила.
- Структуровані JSON-журнали містять змінну за кожним рішенням, тож оператор читає з самого рядку журналу, чому звіт було відкинуто.

### Публічна точка приймання, захищена за замовчуванням

- Усі обмеження увімкнені за замовчуванням: ліміт тіла, ліміт запитів на клієнта, білий список типів вмісту, обмеження глибини JSON і довжини масивів, а також перевірка схеми для кожного типу.
- Рядки запиту та фрагменти вилучаються з URL, які несе звіт, бо URL звіту часто містить токен; перемикач зберігає їх, коли потрібне повне значення.
- Ніколи не експортується нічого неперевіреного: звіт, який сервіс не може прочитати, рахується з причиною й відкидається.
- На preflight CORS для методів надсилання є відповідь, з необовʼязковим білим списком джерел; без налаштування підходить будь-яке джерело, бо надсилання міжсайтове за природою.

### Одна точка приймання для всіх звітів, які може надіслати сайт

- Приймає пакети Reporting API, старі тіла `report-uri` від CSP, журнали помилок мережі та звіти SMTP TLS на одному endpoint, тож не треба розгортати окремий збирач для кожного типу звітів.
- Один POST перетворюється на один запис логу на звіт, готовий для стеку Loki, Tempo та Grafana, який у вас уже є: запит ніколи не бачить цілий пакет як один рядок.
- Старе тіло CSP нормалізується до форми Reporting API, тож запиту не байдуже, який механізм використав браузер.
- Тип звіту, про який ця версія ніколи не чула, все одно доходить із цілісним тілом: Reporting API — це відкритий перелік, і новий тип не є причиною втратити звіт.
